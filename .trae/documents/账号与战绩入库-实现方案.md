## 一、Context：为什么是这一步

- 阶段 3 只剩两块没做：**账号体系**与**玩家数据持久化**（原计划里是「MySQL + MySqlDataStore + NetworkAuthenticator」）。
- 用户已确定的推进原则：**先把不需要真云机就能做完的做掉**，等卡在"只有公网才能验证"的事情上再决定买服务器。
- 本阶段**全部可在本机验证**：MySQL 8 已在本机运行（`MySQL80` 服务、3306 监听），后端也在本机。不需要买云机。
- 做完后的直接收益：玩家有真昵称（不再是"玩家 1/2/3"）、对局战绩真的入库（简历上"数据入库"这句才落地）。

## 三、关键设计决策（这几条是面试能讲的）

1. **后端在同一个进程里扩展，不新建工程。**
   `Backend/RoomRegistry` 已是 Minimal API + `net10.0`。把账号表与房间登记表放在同一个服务里：云机上只起一个后端进程，`-lobbyserver` 一个参数搞定两件事，部署与运维成本最低。
   → `Program.cs` 拆成 `Program.cs` / `Db.cs` / `AuthEndpoints.cs` / `StatsEndpoints.cs`，代码分文件、进程不分裂。

2. **密码 PBKDF2 加盐哈希；token 用「不透明随机串 + 哈希入库 + 过期」，不用 JWT。**
   - 密码：`PBKDF2(SHA-256, salt, iterations)` 存 `password_hash` + `salt`，**数据库里绝不出现明文**。`iterations` 单独存一列，方便以后提高强度而不影响老密码。
   - token：`RandomNumberGenerator` 生成 32 字节随机串，**原文只在注册/登录响应里回给客户端一次**，库里只存 `SHA256(token)` 的十六进制。
     为什么不用 JWT（面试可答）：无状态 JWT **不能即时吊销**，还要管理签名密钥轮换；不透明 token 一行 `DELETE FROM tokens` 就能登出/踢人，对这个体量的项目更简单也更安全。
   - 有效期 30 天；过期清理照抄房间 TTL 的惯例——**每次请求顺手 sweep，不起后台定时器**。

3. **不替换 `IDataStore`（这是对规划文档一处判断的修正）。**
   `项目规划-定稿.md` 写"`IDataStore` 换 `MySqlDataStore` 实现，接口不变"，实测站不住：
   - 接口是**同步**的（`float GetFloat(...)` 直接返回），而远程存储必然是**异步**的 → 接口一改，调用方全改；
   - 更关键：唯一的消费者 [SettingsManager.cs](file:///d:/unitydemo/Blow up your brother/Assets/_Project/Scripts/Game/SettingsManager.cs#L83-L89) 走 `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]`，**开机那一刻还没登录、没有 token**，同步接口在结构上取不到账号数据；
   - 它现在只有 4 个键（鼠标灵敏度/音量/两个开镜灵敏度），本质是**设备本地手感参数**（跟耳机、显示器、鼠标有关），本来就不该跟着账号走。
   → 结论：**设置留本地，玩家档案另做一套服务**。**顺带收益**：token 本身用 `DataManager.Store.SetString("auth_token", ...)` 存 —— `IDataStore` 多了第二个消费者，正好证明这个抽象没白留。

4. **战绩必须由「服务器」上报，不能让客户端自己报。**
   客户端上报有两条路都是坑：按昵称认领自己的行会在重名/重开局时错；让客户端自己填 kills 等于把战绩交给客户端，面试直接减分。
   → 服务器在 `EndMatch` 后遍历 `NetworkServer.connections`，从每个人的游戏玩家上取 token，**每人由服务器 POST 一次**。客户端零上报代码，且天然"每人恰好一次"。
   锚点：[MatchState.cs](file:///d:/unitydemo/Blow up your brother/Assets/_Project/Scripts/Match/MatchState.cs#L84-L95) 的 `EndMatch` 里 `if (IsOver) return;`（第 87 行）是全场唯一的权威结束路径。

5. **`AuthService` 复用 `LobbyService.BaseUrl` / `HasService`，不引入第二个配置开关。**
   一个开关天然满足"未配置就整体关闭"的约束：没配 `-lobbyserver` 时账号功能也自动关闭，局域网/单机流程一行代码都不用动。

6. **推迟 NetworkAuthenticator。** 理由见"不做"列；它属于"必须真云机才能完整验证"的功能，正好落在用户说的"到时候再决定买服务器"那一类。

## 四、分步实施（4 步，每步单独验收）

### 步骤 1：后端账号接口 + 数据库 schema（可独立验收，不碰 Unity）

**新增**
- `Backend/RoomRegistry/schema.sql`：`CREATE DATABASE IF NOT EXISTS blowyourbrother`（utf8mb4）+ 三张表 + 索引
- `Backend/RoomRegistry/Db.cs`：连接串读取 + 建 `MySqlDataSource` + PBKDF2 哈希/校验 + token 生成/校验 + 过期 sweep
- `Backend/RoomRegistry/AuthEndpoints.cs`：注册 / 登录 / 登出 / 查档案

**改**
- `Program.cs`：挂上账号路由；**启动时打印数据库连接状态**
- `RoomRegistry.csproj`：加 `<PackageReference Include="MySqlConnector" .../>`（唯一新增依赖）
- `启动登记服务.bat`：加 `set MYSQL_CONN=...` 一行

**Schema 要点**
| 表 | 字段（关键） |
|---|---|
| `users` | `id BIGINT UNSIGNED AI PK`、`username VARCHAR(32) UNIQUE`、`password_hash VARBINARY(32)`、`salt VARBINARY(16)`、`iterations INT`、`nickname VARCHAR(32) UNIQUE`、`created_at`、`last_login_at` |
| `player_stats` | `user_id PK/FK→users ON DELETE CASCADE`、`level INT DEFAULT 1`、`exp INT DEFAULT 0`、`matches/wins/kills/deaths INT DEFAULT 0`、`updated_at ON UPDATE` |
| `tokens` | `token_hash CHAR(64) PK`、`user_id FK→users ON DELETE CASCADE`、`created_at`、`expires_at`、索引 `(user_id)` 与 `(expires_at)` |

- 排序规则用 `utf8mb4_general_ci` → `username` 唯一索引天然大小写不敏感，杜绝 `Alice` / `alice` 重号。
- 接口返回一律 camelCase（沿用现有约定，正好给 `JsonUtility` 解析）；错误统一 `{"error":"中文原因"}`。

**接口**
- `POST /api/auth/register`（body: username/password/nickname）→ 建用户 + `player_stats` 默认行 + **直接返回 token**（省一次往返）
- `POST /api/auth/login` → 校验密码 → 发新 token
- `POST /api/auth/logout`（Bearer）→ 删掉该 token
- `GET /api/profile`（Bearer）→ 用户 + 战绩

**⚠️ 必须保证**：数据库连不上时**不能让进程退出**，只打印警告，房间登记照常服务 —— 否则会破坏现有的联机调试。

**验收（无需 Unity）**
1. `Get-Content Backend\RoomRegistry\schema.sql | & D:\mysql9\mysql-9.2.0-winx64\bin\mysql.exe -u<用户> -p`
2. 起服务 → `POST /api/auth/register` 拿 token；重复注册返回 `{"error":"用户名已存在"}`
3. `GET /api/profile` 带 token → level 1、战绩全 0；带假 token → 401

## 六、前置条件 / 风险 / 待确认

| # | 事项 | 说明 |
|---|---|---|
| 1 | **需要你提供 MySQL 账号密码** | 后端连接串走环境变量 `MYSQL_CONN`，默认值里密码是占位的 `CHANGE_ME`。要么给我本机 root 密码，要么新建一个专用账号（更规范，建议后者） |
| 2 | **NuGet 联网一次** | `MySqlConnector` 是唯一新增依赖，第一次 `dotnet restore` 需要联网（之后缓存在 `~/.nuget`，离线可编译）。若你的环境完全离线，退路是把账号存 JSON 文件——但那就丢掉"入库"这个阶段目标了 |

## 七、端到端验收（本阶段整体）

1. 本机起 MySQL + 后端（`启动登记服务.bat`）→ 房间登记照常工作（回归验证：不破坏 3-C/3-D）
